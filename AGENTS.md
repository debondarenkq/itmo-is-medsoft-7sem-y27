# Практики проекта

- UI лабораторных находится в `macos/`, самостоятельные Go-сервисы — в `services/`.
- Продолжать существующую структуру: Go `internal/models`, `internal/pkg/modules`, `internal/pkg/storage`, `internal/pkg/adapters`, `internal/app/api`, `internal/app/server`, миграции Goose. Не создавать общий Go-модуль и зависимости между исходниками сервисов.
- В Swift писать максимально просто: обычные SwiftUI View, небольшие функции, понятные имена. Не вводить собственные UI-фреймворки, сложные обобщения и лишние слои. Экраны складывать по функциям в `Features/`, сетевой код в `Core/Networking/`, общие элементы в `UI/`, состояние приложения в `App/`.
- Бизнес-правила и права доступа проверять на сервере. UI показывает доступные действия и серверные ошибки.
- Исходные HTTP-контракты находятся в `contracts/`; сгенерированные Go/Swift-файлы менять генератором `make generate-contracts`.
- Сохранять изменения пользователя. Проверять Go через `make check test`, БД через `make integration`, UI через `./macos/build.sh`.
- Не добавлять в Git пароли, TOTP-секреты, токены и закрытые ключи. Локальные учебные сертификаты и ключи находятся в игнорируемом `deploy/security/`: `tls/ca`, `tls/server`, `jwt`, `services`.
- В нативном клиенте сохранять возможность просмотра полученных серверных TLS-сертификатов (окно «Сертификаты сервера»). Подключать наблюдение ко всем сетевым путям, сохраняя системную проверку доверия.
- Основной запуск backend — кнопки ▶/■ группы `his` в Docker Desktop; на этом Mac используется `desktop-linux`. Проект в Colima остановлен, не поднимать его параллельно. Пересборка — `make prepare` / `make prepare-local`; обычный запуск не должен пересобирать образы и обращаться к реестрам. В CLI учитывать `scripts/docker.sh` и локальный `deploy/docker-context`, не менять глобальный контекст без необходимости.
