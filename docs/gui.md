# Нативный интерфейс HIS

Основной клиент находится в `macos/`: Swift 6, SwiftUI, macOS 14+. Запуск и сборка описаны в `macos/README.md`. Предыдущий Flutter-клиент сохранён в `desktop/` для сравнения; существующие изображения в `docs/screenshots/` относятся к нему.

## Системные компоненты

`NavigationSplitView` разделяет боковую панель и рабочую область. `Table` показывает списки, `Form` с grouped-стилем — редакторы. Панель инструментов, кнопки, поля, диалоги, календарь и отступы используют настройки macOS по умолчанию. Размеры задаются только для окон и панелей; собственного UI kit, шрифтов и цветовой темы нет. Светлая и тёмная темы следуют системным настройкам.

При запуске открывается вход: администратор использует пароль и TOTP, медработник — логин и пароль. Профиль определяется аккаунтом. Администратору доступны справочники, аккаунты и аудит, медработнику — пациенты. Внизу боковой панели находится выход.

## Администрирование

Список медработников содержит имя, должность и статус. Доступны поиск, пагинация, просмотр удалённых, создание, изменение и мягкое удаление. Справочник диагнозов содержит код и название, поддерживает CRUD и импорт из системного диалога выбора JSON. Содержимое файла проверяется сервисом каталога.

## Пациенты

Таблица показывает ФИО, дату рождения, административный пол и наличие ЭМК. Карточка пациента открывается для просмотра и позволяет перейти к редактированию, ЭМК или удалению. Редактор содержит имя, фамилию, необязательное отчество, системный календарь даты рождения, пол и комментарий. Сервис определяет допустимость изменений и удаления, клиент показывает его ошибку.

## Электронная медицинская карта

Карта открывается отдельной панелью. Если её ещё нет, пользователь создаёт её от имени медработника вошедшего аккаунта. Обычный режим — просмотр. Для редактирования врач подтверждает разблокировку; автор берётся из текущего профиля.

Диагнозы выбираются из серверного справочника. Таблица показывает дату добавления, код, название и статус; даты и удалённые записи берутся из серверной истории. Восстановление ранее сохранённого удалённого диагноза добавляет его заново через существующую команду API; сервис проверяет доступность справочника. Отмена удаления в текущем черновике сохраняет исходную запись. Назначения можно добавить, изменить, отменить и удалить. Действия накапливаются в локальном черновике; сервер получает команды, автора и исходную версию карты одним запросом. Сохранение возвращает карту в режим просмотра. Серверные ошибки сохраняют введённые данные. Конфликт версии предлагает обновить карту с подтверждением отмены черновика.

История содержит автора, дату и время события, данные до и после изменения. Просмотр на выбранную версию или момент времени выполняется запросом к сервису. Историческое состояние доступно только для чтения.

## Границы клиента

На клиенте остаются навигация, выбор файла, ввод дат, отображение сообщений и состояние черновика. Бизнес-проверки, ограничения полей, уникальность, доступность ссылок, права автора на изменение и атомарность операций принадлежат Go-сервисам. Swift DTO и методы HTTP генерируются из корневых OpenAPI-контрактов с отключённой генерацией локальной валидации.
