# План десктопного интерфейса HIS

Flutter для macOS и Windows, Material 3, встроенный Navigator. Разделы администратора и медработника выбираются без аутентификации. Документ описывает реализованный UI. Запуск и сборка — в `desktop/README.md`.

## Администратор: список медработников

Боковое меню: «Медработники», «Справочники → Диагнозы». Таблица: фамилия и имя, должность, статус «Активен»/«Удалён», действия редактирования и мягкого удаления. Кнопка «Добавить медработника». Для отображения удалённых сотрудников список запрашивается с `include_deleted=true`.

## Администратор: карточка медработника

Поля: фамилия, имя, должность (3–24 символа). Должность в API — свободный текст; UI может предложить варианты с возможностью ввода. Действия: сохранить, отменить, вернуться к списку, пометить удалённым. Отчество медработника не предусмотрено заданием. Удалённая карточка доступна для просмотра; восстановление сотрудника пока не входит в контракт backend.

## Администратор: справочник диагнозов

Новый справочник пуст. Таблица: код, наименование, редактирование и удаление. Кнопки «Добавить диагноз» и «Загрузить из файла». Выбор файла выполняется на стороне клиента; его JSON-содержимое отправляется в `/api/v1/diagnoses/import`. Показываются результат и ошибки конкретных записей, при ошибке весь импорт откатывается. Пять учебных примеров представлены отдельным файлом `examples/diagnoses.json`, который пользователь выбирает явно.

Код содержит ровно 6 символов по заданию; пример `E11.900` из описания макета содержит 7 и не проходит валидацию. Пример для реализации: `E11.00`.

## Медработник: список пациентов

Таблица: ФИО, дата рождения, пол М/Ж/НУ, наличие ЭМК, просмотр/редактирование/удаление. Кнопка «Добавить пациента». Пациента с ЭМК удалить нельзя; UI отражает запрет, backend обеспечивает его независимо от UI.

Выбранный сотрудник может отображаться в меню, но отношения «закреплённый врач пациента» в задании нет. Раздел «Мои пациенты» не реализуется как отдельная выборка без определения этого отношения; основной экран показывает общий список пациентов.

## Медработник: карточка пациента

Поля: фамилия, имя, необязательное отчество, дата рождения с календарём, административный пол, комментарий до 32 символов. Действия: сохранить, отменить, вернуться к списку, удалить пациента без ЭМК. Для пациента с картой — «Открыть ЭМК»; без карты — «Создать ЭМК» с обязательным выбором активного медработника.

## ЭМК

Вверху — данные пациента. Вкладки: «Диагнозы», «Назначения», «История изменений». По умолчанию только просмотр. Разблокировка требует выбора активного сотрудника и явного подтверждения; при сохранении передаются `staff_id`, версия карты и набор команд. После успешного сохранения UI снова блокируется, отмена отбрасывает черновик, конфликт версии сохраняет черновик и предлагает обновить карту.

Диагнозы: добавить из справочника, удалить из текущего списка. Сведения об удалённых диагнозах и датах доступны в истории. Повторное добавление доступного диагноза из справочника создаёт новую запись и событие добавления; история прежнего удаления сохраняется.

Назначения: добавить, изменить, отменить. При изменении backend удаляет старое и добавляет новое назначение одной транзакцией; отменённые назначения отображаются со статусом «Отменено».

История: время, автор и действие с данными до/после изменения; выбор момента времени или версии для просмотра восстановленного состояния. Даты и авторы берутся из истории backend, отображение времени — в локальном часовом поясе пользователя.
