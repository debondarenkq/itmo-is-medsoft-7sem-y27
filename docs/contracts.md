# Контракты и генерация кода

Источник HTTP-контрактов всех сервисов — корневой каталог `contracts/` со схемами в формате OpenAPI 3.0.3. Поля запросов/ответов, типы, UUID, календарные даты, timestamp, enum, обязательность полей, ограничения и маршруты описываются здесь.

| Сервис | Источник | Сгенерированный код |
|---|---|---|
| Медработники | `contracts/staff.yaml` | `services/staff/api/generated.gen.go` |
| Диагнозы | `contracts/catalog.yaml` | `services/catalog/api/generated.gen.go` |
| Пациенты и ЭМК | `contracts/clinical.yaml` | `services/clinical/api/generated.gen.go` |

`services/<service>/api/openapi.yaml` — автоматически обновляемая локальная копия соответствующего контракта. Она сохраняется вместе с сервисом для его самостоятельной сборки и генерации. Редактируется только схема в корневом `contracts/`.

`openapi.json` рядом с локальным YAML — сгенерированная JSON-документация. Сервис отдаёт её через `/openapi.json`; вручную этот файл не редактируется. Копия схемы также встраивается генератором в Go-код.

## Go-обработчики

`oapi-codegen` v2.8.0 генерирует:

- структуры DTO и enum;
- `RequestObject` с типизированными path/query/body;
- `ResponseObject` и типы допустимых успешных/ошибочных ответов;
- `StrictServerInterface`, который реализует API-слой;
- адаптер маршрутов и JSON-binding для `gorilla/mux`;
- HTTP-клиенты для межсервисных вызовов — отдельно в адаптерах, только для используемых операций `GetStaff` и `GetDiagnosis`. Серверные пакеты `api` собственных HTTP-клиентов не генерируют.

Например, ID пациента определяется контрактом как `type: string`, `format: uuid` и превращается в `uuid.UUID`:

```go
func (implementation *Implementation) GetPatient(
    ctx context.Context,
    request contract.GetPatientRequestObject,
) (contract.GetPatientResponseObject, error) {
    if err := validation.RequireID(request.ID); err != nil {
        return nil, err
    }
    patient, err := implementation.Module.GetPatient(ctx, request.ID.String())
    if err != nil {
        return nil, err
    }
    response, err := toPatient(patient)
    if err != nil {
        return nil, err
    }
    return contract.GetPatient200JSONResponse(response), nil
}
```

ID и query-параметры разбирает сгенерированный adapter; тело декодируется в `request.Body`. В ручках нет `mux.Vars`, ручного `strconv` и `json.Decoder`. `RequireID` проверяет только бизнес-ограничение «UUID не нулевой», а не парсит строку.

Перед binding middleware проверяет запрос по схеме: обязательные поля, UUID/даты, enum, длины, диапазоны, массивы и неизвестные поля. Бизнес-модуль отдельно проверяет смысл операций: активность медработника, соответствие полей типу команды, наличие карты, конфликт версии и ограничения удаления.

Транспортные DTO явно преобразуются в бизнес-модели и обратно. Хелперы конкретной ручки находятся в её файле, общие преобразования — в `internal/app/api/service.go`. Мапперы ответов возвращают ошибку, если UUID, календарная дата или JSON-снимок из хранилища некорректны; HTTP-слой передаёт её общему обработчику ошибок, который логирует причину и отвечает 500 без раскрытия внутренних данных. Пустые списки состояния сериализуются как `[]`, отсутствующие снимки истории — как `null`. Бизнес-модели и данные БД не заменяются HTTP-структурами. История сохраняет собственные долговечные снимки.

## Межсервисные вызовы

Клинический сервис использует сгенерированные HTTP-клиенты:

- `internal/pkg/adapters/staffapi`: контракт медработников;
- `internal/pkg/adapters/catalogapi`: контракт справочника.

YAML этих клиентов копируется из корневого `contracts/` при общей генерации, а Go-код генерируется внутри клинического сервиса. Это локальные копии внешних контрактов, которые не редактируются отдельно. Благодаря этому сервис собирается из своего каталога без импортов соседних Go-модулей, общего `go.mod`, `go.work` или `replace`. Оба клиента используют один `GATEWAY_URL` и обращаются к владельцам контрактов через Nginx. Межсервисный таймаут — 3 секунды.

## Flutter

`desktop/api/openapi.json` — объединённое описание публичного gateway, автоматически собранное из трёх сгенерированных спецификаций. Это производный файл, а не отдельный редактируемый контракт.

OpenAPI Generator v7.26.0 создаёт пакет `desktop/packages/his_api` с DTO, enum, сериализацией и HTTP-методами. В клиенте один `contract.ApiClient` для одного адреса Nginx; `StaffApi`, `DiagnosesApi`, `PatientsApi`, `RecordsApi` — группы публичных ресурсов, не адреса микросервисов.

Формы создают типизированные `StaffInput`, `DiagnosisInput`, `PatientInput`, а черновик ЭМК — `Command`. Ручной сборки URL и JSON для обычных операций нет. UI-модели отдельно отображают полученные контрактные объекты.

Для необязательных полей используется `Optional`: отсутствие поля отличается от явно переданного null. Это важно для команд ЭМК, чтобы не отправлять `id: null` в команде добавления назначения. При импорте содержимое выбранного файла передаётся исходным текстом, включая неизвестные поля и некорректный JSON. Сериализатор gateway пропускает этот документ без повторного JSON-кодирования; структуру и содержимое проверяет backend.

## Изменение и проверка

Редактируйте соответствующий YAML в `contracts/`, затем из корня:

```sh
make generate-contracts
```

Нужны Go 1.26, Docker и Python 3. Генератор Go закреплён как Go tool в каждом `go.mod`; версия генератора Dart закреплена в скрипте. Если локального Dart нет, форматирование выполняется через SDK в Docker.

После синхронизации корневых контрактов для отдельного сервиса можно выполнить `go generate ./api` внутри его каталога. Эта команда использует локальный снимок схемы; изменение корневого контракта распространяется командой `make generate-contracts`. Для клинического сервиса внешние клиенты также генерируются через `go generate ./internal/pkg/adapters/staffapi ./internal/pkg/adapters/catalogapi` из сохранённых локальных схем.

Сгенерированные файлы сохраняются в Git и не правятся вручную. После генерации проверьте изменённые мапперы и бизнес-логику, затем выполните тесты. При добавлении или изменении методов компилятор проверяет соответствие `StrictServerInterface`. CI workflow Contracts повторно генерирует код и требует пустой `git diff`, чтобы обнаруживать несогласованные правки контрактов и DTO.

## Если IDE не распознаёт UUID или метод String

`openapi_types.UUID` в сгенерированных DTO — alias `uuid.UUID` из `github.com/google/uuid`, у которого есть метод `String()`. Сообщение `Unresolved reference 'String'` само по себе не означает, что нужно менять DTO или писать свой метод.

Сначала проверьте сборку из каталога соответствующего сервиса:

```sh
cd services/clinical
go version
go mod download
go test ./...
```

SDK IDE должен поддерживать Go 1.26, а Go modules должны быть включены для всех трёх самостоятельных модулей в `services`. Корень репозитория не является Go-модулем; запускать `go test ./...` из него нельзя. Для общей проверки используйте `make test` и `make check`.

Если скачивание публичных зависимостей завершается `403 Forbidden` от корпоративного Go proxy, можно выбрать публичный proxy только для текущей команды:

```sh
GOPROXY=https://proxy.golang.org,direct go mod download
```

Повторите для каждого сервиса и выполните синхронизацию Go-модулей в IDE. Глобально менять настройки Go или добавлять общий `go.work` для этого не требуется.
