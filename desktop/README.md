# МедКарта — десктопный клиент HIS

Flutter-приложение для macOS и Windows. Интерфейс на русском языке, Material 3, встроенный Navigator, белая/бирюзовая/зелёная палитра. Все данные загружаются из настоящего backend; при отсутствии соединения показывается ошибка с повторной загрузкой.

## Запуск

Нужен Flutter 3.44 или новее. Для macOS нужен полный Xcode с выбранным developer directory; для Windows — Visual Studio с компонентами Desktop development with C++. Проверьте окружение через `flutter doctor`.

Сначала запустите backend из корня репозитория:

```sh
docker compose up --build -d --wait
```

Затем из `desktop/`:

```sh
flutter pub get
flutter run -d macos
```

На Windows:

```powershell
flutter pub get
flutter run -d windows
```

Клиент обращается к единственной точке входа `http://localhost:8080`. Для другого адреса:

```sh
flutter run -d macos --dart-define=API_BASE_URL=http://192.168.1.10:8080
```

Адрес также можно изменить в приложении через «Подключение». Здесь указывается адрес Nginx, а не отдельного микросервиса. Для обращения к backend с другого компьютера нужно опубликовать порт Nginx на доступном сетевом интерфейсе; текущий Compose публикует его только локально.

## Работа в приложении

- В меню выбирается рабочее место «Администратор» или «Медработник», без логина.
- Администратор создаёт и изменяет сотрудников, отмечает их удалёнными; управляет справочником диагнозов.
- «Загрузить из файла» открывает системный диалог выбора JSON. Формат: `{"diagnoses":[{"code":"TEST01","name":"Учебный диагноз"}]}`. Пример — `../examples/diagnoses.json`. Справочник не заполняется автоматически.
- Медработник создаёт, просматривает и изменяет пациентов. Удаление пациента с ЭМК заблокировано и в интерфейсе, и в backend.
- Для создания ЭМК и разблокировки редактирования обязательно выбирается активный сотрудник.
- Изменения диагнозов и назначений накапливаются в черновике. «Сохранить изменения» отправляет их атомарно и возвращает карту в режим просмотра. «Отмена» отбрасывает черновик с подтверждением. Переход в другой раздел с несохранёнными изменениями также требует подтверждения.
- Удалённый диагноз можно восстановить, если он доступен в справочнике. Его прежняя история сохраняется.
- Новое назначение в черновике можно изменить или убрать. Существующее назначение можно изменить, сохранить, затем отменить; отменённые назначения остаются видимыми.
- В истории доступны автор, время, данные до/после и просмотр карты на версию или произвольный момент времени. Историческая карта всегда доступна только для просмотра.
- При конфликте версий черновик сохраняется, а обновление карты требует подтверждения его отмены.

Раздел «Мои пациенты» не вводит отдельную выборку: в задании отсутствует отношение закрепления пациента за врачом. Показывается общий список пациентов.

## Сборка

На macOS:

```sh
flutter build macos --release
```

Приложение: `build/macos/Build/Products/Release/his_desktop.app`.

На Windows:

```powershell
flutter build windows --release
```

Приложение: `build/windows/x64/runner/Release/his_desktop.exe`; запускается вместе с папкой `data` и DLL из этой же сборки.

В репозитории настроен workflow `.github/workflows/desktop.yml`: нативные сборки на macOS/Windows, статический анализ, unit/widget-тесты и прогон GUI с Go API. Готовые приложения доступны как артефакты успешного запуска workflow Desktop.

## Проверки

```sh
flutter analyze
flutter test
dart format --output=none --set-exit-if-changed lib test
```

Unit/widget-тесты проверяют черновики, отмену, сообщения о соединении, валидацию и импорт файла. Интеграционный тест выполняется отдельно с настоящим backend:

```sh
flutter test test/backend_flow_test.dart --dart-define=HIS_INTEGRATION=true --dart-define=API_BASE_URL=http://localhost:8080
```

Для изолированного тестового backend из корня:

```sh
docker compose -p his-frontend-tests -f compose.yaml -f deploy/frontend-test.compose.yaml up -d --wait
```

Его gateway доступен на порту 8090. Тест создаёт синтетические записи. При `--dart-define=SAVE_PREVIEWS=true` сохраняются снимки экранов в `build/previews/`.

Если локальный Flutter не установлен, проверки без нативной сборки можно выполнить через `../scripts/test-desktop.sh`; скрипт использует проверенный SDK в Docker. Docker проверяет Flutter-код и рендеринг виджетов; нативные macOS/Windows-сборки выполняются на соответствующих ОС.

## Структура

- `lib/core/`: модели, единый API-клиент, тема, выбранный сотрудник и черновик ЭМК.
- `lib/screens/`: оболочка с боковым меню и шесть основных экранов.
- `lib/widgets/`: формы, таблицы с поиском/пагинацией, диалоги и состояния загрузки.
- `macos/`, `windows/`: нативные проекты, размер окна и разрешения на сеть/выбор файла.
- `assets/`: локальные шрифты Roboto с лицензией и векторный знак приложения.
- `test/`: unit, widget и интеграционные проверки.

Иконки приложения воспроизводятся командой `python3 ../scripts/generate_desktop_icons.py` из геометрического медицинского креста без внешних зависимостей.
