# Учебная госпитальная информационная система

HIS на Go: пять самостоятельных микросервисов, PostgreSQL и единая точка входа Nginx. LIS имеет отдельный Go-сервис, собственную БД и приложение на Swift. Нативный клиент реализован на Swift 6 и SwiftUI для macOS 14+: интерфейсы администратора и медработника, ЭМК, история и импорт справочника. Все запросы клиента проходят через Nginx. Лабораторная 2 добавляет TLS 1.3, вход с JWT, TOTP администратора, роли, аккаунты и аудит. Полная инструкция по защите — [docs/security.md](docs/security.md). Лабораторная 3: FHIR R5, лабораторные назначения и LIS — [docs/lab3.md](docs/lab3.md).

## Запуск

Пошаговая инструкция, объяснение сертификатов и сценарий показа преподавателю — [docs/defense.md](docs/defense.md).

Один раз подготовьте проект при доступном интернете:

```sh
make prepare
```

Импортируйте `deploy/security/tls/ca/ca.crt` в доверенные SSL-сертификаты macOS. На уже подготовленном ноутбуке пересборка без доступа к Docker Hub выполняется через `make prepare-local` (нужны установленный Go и кэш зависимостей).

Для каждого обычного запуска и защиты:

```sh
make demo
```

На этом ноутбуке проект закреплён за Docker Desktop локальным файлом `deploy/docker-context` (`desktop-linux`). В Docker Desktop → Containers используйте ▶ у группы **his**, чтобы запустить все компоненты, и ■, чтобы остановить. Colima для этого проекта не используется.

Команда запускает готовый Docker Compose-набор и открывает нативный клиент. Сборка и скачивание при запуске не выполняются. `make doctor` проверяет готовность, `make status` показывает контейнеры, `make down` останавливает backend с сохранением данных. `make help` перечисляет команды.

API доступен по `https://localhost:8443/api/v1` после входа. Compose создаёт пять баз HIS с отдельными пользователями и запускает сервисы. Каждый сервис применяет SQL-миграции Goose перед запуском HTTP API; при ошибке миграции процесс завершается. Данные сохраняются в Docker volume между перезапусками. Новая база содержит пустой справочник диагнозов. Записи добавляются вручную или импортируются из выбранного JSON-файла через `POST /api/v1/diagnoses/import`. Пример файла — `examples/diagnoses.json`; он не загружается автоматически.

Скрипт `scripts/compose.sh` выбирает между `docker compose` и отдельным `docker-compose`. `make up` запускает только подготовленный backend без сборки и скачиваний.

PostgreSQL доступен локально на `localhost:55432`, SSL отключён. Для DBeaver используйте базу `staff`, пользователя `staff_user`, пароль `staff_local`; для `identity` — `identity_user` / `identity_local`; для `catalog` и `clinical` — соответственно `catalog_user` / `catalog_local` и `clinical_user` / `clinical_local`.

Отдельный PostgreSQL LIS доступен на `localhost:55436`, база `lis`, пользователь `lis_user`, SSL отключён. Локальный пароль находится в игнорируемом файле `deploy/security/services/database-lis.password`. История анализов LIS хранится в таблице `results`.

Остановка с сохранением данных:

```sh
make down
```

Для выбора HTTPS-порта измените опубликованный порт Nginx в `compose.yaml`. Go-сервисы наружу не публикуются; учебный PostgreSQL доступен только на localhost. Используются только синтетические учебные данные. Клиент проверяет сертификат учебного CA; внешние запросы защищены TLS 1.3 и авторизацией.

## Структура

```text
contracts/        исходные OpenAPI-схемы всех сервисов
services/
  identity/       аккаунты, TOTP, JWT, refresh-токены и аудит
  staff/          медработники, должности и роли; прямой HTTP API для identity
  catalog/        справочник диагнозов
  laboratory/     LOINC, лабораторные назначения, FHIR R5 и результаты
  lis/            клиент HIS, собственная БД и история проведённых анализов
  clinical/       пациенты, ЭМК, назначения, история
    cmd/clinical-service/
    internal/app/api/         HTTP-обработчики
    internal/models/          модели, запросы и обычные ошибки Go
    internal/config/          конфигурация зависимостей
    internal/pkg/modules/     бизнес-логика и интерфейсы зависимостей
    internal/pkg/storage/     PostgreSQL
    internal/pkg/adapters/    HTTP-клиенты справочников
    internal/app/server/      запуск HTTP-сервера, БД и миграций
    internal/validation/      проверки UUID и текстовых полей
    api/                      OpenAPI-контракт и сгенерированные DTO
    migrations/               SQL-миграции Goose
    go.mod
    go.sum
    Dockerfile
macos/             основной нативный клиент Swift + SwiftUI
deploy/            Nginx, инициализация и тестовая конфигурация PostgreSQL
examples/          примеры файлов для ручного импорта
scripts/           запуск Compose и сквозные проверки API
docs/              архитектура и описание API
```

Основной Compose HIS находится в корневом `compose.yaml`; отдельная группа LIS — в `deploy/lis.compose.yaml`.

| Файл в `deploy/` | Назначение |
|---|---|
| `his-nginx.conf` | Вход HTTPS и маршрутизация API HIS |
| `lis-nginx.conf` | Вход HTTPS и маршрутизация API LIS |
| `his-postgres-init.sql` | Первичное создание баз и пользователей HIS |
| `his-laboratory-init.sh` | Первичное создание БД laboratory в PostgreSQL HIS |
| `database-tests.compose.yaml` | Отдельные PostgreSQL для интеграционных тестов БД |
| `his-lis-tests.compose.yaml` | Дополнение к основному Compose для сквозных тестов HIS ↔ LIS |
| `his-ui-tests.compose.yaml` | Дополнение к основному Compose для UI-проверок HIS на отдельном порту |

Каждый сервис имеет собственные `go.mod`, `go.sum`, модели, утилиты, миграции и Dockerfile. Корневой `go.work` перечисляет все шесть модулей для работы с репозиторием в GoLand. Общих Go-пакетов, локальных `replace` и импортов другого сервиса нет. Для сборки достаточно его каталога:

```sh
cd services/clinical
go build ./cmd/clinical-service
docker build -t his-clinical .
```

В GoLand открывайте корень репозитория и выбирайте Go SDK 1.26 или новее в **Settings → Go → GOROOT**. После добавления модуля включайте его в `go.work`. Если проект уже открыт, выполните **File → Reload All from Disk** и дождитесь синхронизации Go-модулей и индексации. Для проверки сервиса независимо от workspace используйте `GOWORK=off go test ./...` в его каталоге.

Миграции включены в исполняемый файл. Для самостоятельного запуска задайте `DATABASE_URL` и выполните `go run ./cmd/clinical-service`: сервис применит миграции и запустит HTTP API. Для остальных сервисов используется соответствующее имя команды. На Windows переменные окружения задаются средствами PowerShell.

Конфигурация:

| Переменная | Где нужна | Значение |
|---|---|---|
| `DATABASE_URL` | Все сервисы | Обязательный адрес собственной PostgreSQL-базы |
| `HTTP_ADDR` | Все сервисы | По умолчанию `:8080` |
| `GATEWAY_URL` | Клинический сервис | Обязательный URL Nginx; в Compose — `http://nginx`, можно переопределить окружением |

Клинический сервис обращается к справочникам через Nginx: `clinical → nginx → staff/catalog`. Адреса конечных сервисов находятся в upstream-блоках `deploy/his-nginx.conf`. При смене адреса staff/catalog обновляется конфигурация Nginx; клинический сервис не нужно менять или пересобирать. Смену IP контейнера за прежним DNS-именем Nginx отслеживает через встроенный DNS Docker.

Если меняется адрес самого gateway, задайте `GATEWAY_URL` и пересоздайте клинический контейнер без пересборки:

```sh
GATEWAY_URL=http://gateway.internal ./scripts/compose.sh up -d --force-recreate clinical-service
```

## API и история ЭМК

[Описание запросов и команд](docs/api.md) и [архитектура](docs/architecture.md).

Спецификации работающего приложения:

- `GET /docs/staff/openapi.json`
- `GET /docs/catalog/openapi.json`
- `GET /docs/clinical/openapi.json`
- `GET /docs/security/openapi.json`

Каждый сервис также отдаёт `/openapi.json`, `/live` и `/ready` на своём порту. По gateway `/live` проверяет сам Nginx; готовность отдельных сервисов проверяется healthchecks Compose.

При создании или изменении ЭМК обязателен `staff_id`. Разблокировка доступна только врачу; сервер независимо проверяет роль и соответствие автора аккаунту. Сохранение карты атомарно: команды, текущее состояние и история записываются одной транзакцией. При изменении диагноза или назначения создаётся одно событие с полными снимками до и после изменения; ID записи внутри ЭМК сохраняется. История хранит полные снимки данных и позволяет восстановить карту по времени или версии. Пациента с ЭМК нельзя удалить даже прямым вызовом API.

## Проверки

Требуется Go 1.26 или новее. Каждый модуль проверяется отдельно; из корня на macOS/Linux:

```sh
make test
make check
make integration
```

`make integration` запускает отдельный PostgreSQL на `127.0.0.1:55433`, выполняет тесты с `-race` и останавливает тестовый Compose-проект. Каждый тест создаёт собственную схему, применяет миграции и удаляет схему после завершения. Проверяются конкурентные операции, ограничения БД, мягкое удаление, загрузка диагнозов, атомарность и восстановление ЭМК. Обычный `make test` запускает unit-тесты; тесты PostgreSQL пропускаются, если не задан `TEST_DATABASE_URL`.

Для отдельного сервиса можно передать `TEST_DATABASE_URL` и выполнить `go test -race -count=1 ./...` внутри его каталога. Используйте отдельную тестовую базу, доступную пользователю с правом создания схем.

Сквозная проверка через Nginx после запуска backend:

```sh
python3 scripts/smoke.py
```

Она выполняет сценарии задания, включая CRUD, изменения ЭМК, исторические снимки, восстановление и ошибки API. Проверка создаёт учебные записи, в том числе ЭМК; карты намеренно не удаляются через API. Для чистой проверки используйте отдельный Compose-проект.

## Приложение для macOS

Инструкция — [macos/README.md](macos/README.md). После запуска backend выполните:

```sh
make demo
```

Нужны macOS 14+ и Xcode 16+. Для запуска из Xcode откройте `macos/HIS.xcodeproj`, выберите **HIS → My Mac** для медработника или **HISAdmin → My Mac** для администратора и нажмите **⌘R**. HIS содержит пациентов и ЭМК, HISAdmin — сотрудников, диагнозы, аккаунты и аудит. `make demo` открывает оба приложения; `make demo-worker` и `make demo-admin` — выбранное. Адрес Nginx задаётся отдельно в меню каждого приложения → Настройки… (`⌘,`). Workflow [macOS](https://github.com/debondarenkq/itmo-is-medsoft-7sem-y27/actions/workflows/desktop.yml) собирает оба `.app` и публикует ZIP.

## Контракты

HTTP API описывается в корневом каталоге [`contracts/`](contracts/README.md). Локальные схемы в сервисах обновляются генератором и не редактируются вручную. Go DTO, интерфейсы ручек, binding для gorilla/mux и HTTP-клиенты генерируются через `oapi-codegen`. SwiftUI-приложение использует сгенерированный Swift-пакет `macos/Generated` для единственного gateway. Подробности — [docs/contracts.md](docs/contracts.md). После изменения YAML выполните `make generate-contracts`; CI проверяет отсутствие расхождений между схемами и кодом.

Для демонстрации выполните `make reset` (синоним — `make reset-demo`). Команда **пересоздаёт контейнеры и тома HIS и LIS, удаляя все текущие данные**, и загружает учебный набор: 5 сотрудников, 6 диагнозов, 6 пациентов, 3 ЭМК с историей и 7 назначений анализов. `make fresh` запускает систему с нуля без демоданных. Аккаунты не создаются. Настройте администратора в HISAdmin, затем запустите `make demo-accounts`: отдельный скрипт создаст четыре демо-аккаунта через обычный HTTPS API. Он запросит пароль и TOTP администратора; выданные пароли сотрудников сохранит в локальный `build/demo-accounts.json`. Скрипт можно запускать и без reset — недостающих демо-сотрудников он создаст через API. Подробности — [docs/security.md](docs/security.md).

Для полностью пустой учебной установки выполните `./scripts/compose.sh down -v`, затем `make up`. Это удаляет текущие базы; сотрудники и аккаунты создаются заново через приложение. Перенос данных из прежних версий не поддерживается.
