# LIS service

Самостоятельный клиент FHIR API HIS с собственной БД `lis` и нативным интерфейсом `LIS.app`. Не хранит локальную очередь HIS; сохраняет неизменяемую историю проведённых исследований со снимками ресурсов. Вход пользователя LIS не требуется по условиям задания. API сервиса публикуется только на localhost через отдельный HTTPS gateway.

Обязательные переменные — `DATABASE_URL` и `GATEWAY_URL`; `HTTP_ADDR` по умолчанию `:8080`. В Compose `GATEWAY_URL=http://his-gateway`: обращение к HIS идёт через Nginx по внутреннему DNS-имени в сети `his_gateway`. Адрес не передаётся клиентом и не хранится в БД. Пользователь вводит только API-ключ; сервер получает токены и сразу подтверждает доступ с ролью LIS. В БД остаются только токены, API-ключ не сохраняется. При HTTPS gateway `HIS_CA_FILE` добавляет публичный доверенный CA; без него используются системные корни.

Контракт — `contracts/lis.yaml`, клиенты HIS генерируются локально из `laboratory.yaml`, `fhir.yaml` и `security.yaml`. Запуск независимо от HIS — `make lis-up`, остановка — `make lis-down`. Проверки — `go test ./...`, `go vet ./...`, `make integration`, `make integration-his-lis`. Подробности: [лабораторная 3](../../docs/lab3.md).

`DATABASE_PASSWORD_FILE` загружает пароль БД из локального игнорируемого файла. В Compose новые пароли не хранятся в исходниках; `make certs` создаёт их один раз.
